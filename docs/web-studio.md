# Minecraft 皮肤绘制工具（像素画板 + 实时 3D 预览）

一个**离线可用**的网页工具：在左侧画布上逐像素绘制 Minecraft 皮肤（64×64 或 64×32），
右侧立刻显示这个皮肤的**立体效果**，可以拖动旋转、滚轮缩放、播放行走/挥手动画。

工作目录里的两张参考图已经过校验，可以直接用本工具打开：

| 文件 | 尺寸 | 格式 |
|---|---|---|
| `苦力怕娘.png` | 64×64 | 现代格式（含第二层：帽子/外套/袖/裤） |
| `HIM.png` | 64×32 | 旧版格式（只有基础层） |

---

## 一、怎么打开

**方式 1：直接双击 `index.html`**（推荐，无需服务器、无需联网）
本项目全部脚本都是普通 `<script src>`，所以 `file://` 直接打开就能用。

**方式 2：起一个本地服务器**（某些浏览器对 `file://` 更严格时）

```powershell
# 在项目目录下
python -m http.server 8000
# 然后浏览器打开 http://127.0.0.1:8000/index.html
```

> 打开后底栏会显示「自测 N 通过 / 0 失败」。看到 0 失败就说明所有模块工作正常。

## 二、怎么用

1. **画**：左键按住拖动即可连续作画（自动补点，不会断线）。
   - 工具：铅笔 / 橡皮 / 填充 / 吸管 / 直线 / 矩形（快捷键 `P` `E` `F` `I` `L` `R`，或 `1`–`6`）
   - **右键 = 吸管**（取走画布上的颜色）
   - 笔刷 1–4、不透明度 0–255、缩放 2–24 倍
   - `Ctrl+Z` 撤销，`Ctrl+Shift+Z` / `Ctrl+Y` 重做；一次拖拽 = 一步撤销
   - 「对称」打开后左右对称作画
2. **看立体效果**：中间面板即 3D 预览，拖动旋转、滚轮缩放，「复位」回到默认视角。
   可切换动画（站立呼吸 / 行走 / 挥手）、自动旋转、光照、地面，还能单独隐藏某个部位来做对照。
   > **一旦你开始拖动/滚轮，自动旋转会自动关闭**（按钮状态同步变灰），把视角完全交给你；
   > 想继续自动旋转再点一下「自动旋转」即可。
3. **打开 / 保存**：
   - 「打开皮肤…」或**把 PNG 拖进页面**即可载入（自动识别 64×64 / 64×32）
   - 「保存 PNG」导出 64×64；「保存 64×32」导出旧版格式
   - 「导出 3D 截图」把当前立体画面存成 PNG
4. **搞不清哪块像素是哪个部位？**
   打开「部位标注」，画布上会标出区域外框与中文名称（如「头·正面」「右臂」）；
   **名称只写在空白（透明）像素上，绝不会盖住你画的内容** —— 已绘制的区域只有彩色外框，
   鼠标移上去时顶部一行会立刻告诉你**这个像素属于哪个部位、哪个面、哪一层**。
   右侧「贴图 ↔ 立体部位 对照」面板里还有完整对照表。

## 三、Minecraft 皮肤贴图 ↔ 立体部位 对照（重点）

皮肤贴图是一张**展开图（UV 图）**：把方块人剪开摊平。理解它只需要记住两条规则。

### 规则 1：每个方块都是「十字带」

同一个方块的 6 个面在贴图上排成一条十字形的带子：

```
            [ 顶面 ]
[ 右面 ][ 正面 ][ 左面 ][ 背面 ]
            [ 底面 ]
```

也就是说，**一条 4 格宽的横条，从左到右读作「右面、正面、左面、背面」**；
它上方接顶面、下方接底面。这里的「右面」是**角色自己的右手边**。

### 规则 2：各个部位的方块尺寸不同，所以横条高度不同

| 部位 | 方块尺寸（宽×高×厚，单位像素） | 贴图上的一块 |
|---|---|---|
| 头 | 8×8×8 | 32×16 的一带 |
| 躯干 | 8×12×4 | 40×16 的一带 |
| 手臂 | 4×12×4 | 16×16 的一带 |
| 腿 | 4×12×4 | 16×16 的一带 |

### 64×64（现代格式）完整坐标表

单位为像素，坐标是贴图左上角为 (0,0) 的 `x, y, 宽×高`。

| 部位 / 面 | 贴图区域 |
|---|---|
| 头 顶面 | 8, 0, 8×8 |
| 头 底面 | 16, 0, 8×8 |
| 头 右面 | 0, 8, 8×8 |
| 头 正面 | 8, 8, 8×8 |
| 头 左面 | 16, 8, 8×8 |
| 头 背面 | 24, 8, 8×8 |
| 躯干 顶面 | 20, 16, 8×4 |
| 躯干 底面 | 28, 16, 8×4 |
| 躯干 右面 | 16, 20, 4×12 |
| 躯干 正面 | 20, 20, 8×12 |
| 躯干 左面 | 28, 20, 4×12 |
| 躯干 背面 | 32, 20, 8×12 |
| 右臂 顶面 | 44, 16, 4×4 |
| 右臂 底面 | 48, 16, 4×4 |
| 右臂 右面 | 40, 20, 4×12 |
| 右臂 正面 | 44, 20, 4×12 |
| 右臂 左面 | 48, 20, 4×12 |
| 右臂 背面 | 52, 20, 4×12 |
| 右腿 顶面 | 4, 16, 4×4 |
| 右腿 底面 | 8, 16, 4×4 |
| 右腿 右面 | 0, 20, 4×12 |
| 右腿 正面 | 4, 20, 4×12 |
| 右腿 左面 | 8, 20, 4×12 |
| 右腿 背面 | 12, 20, 4×12 |
| 帽子（头外层） | 头的所有区域 x + 32（即 32,0 起） |
| 外套（躯干外层） | 躯干的所有区域 y + 16（即 y=32 起） |
| 右袖（右臂外层） | 右臂的所有区域 y + 16 |
| 右裤（右腿外层） | 右腿的所有区域 y + 16 |
| **左臂** | 左臂独立区：`36,48` 起（正面），右面 `32,52`，左面 `40,52`，背面 `44,52`，顶面 `36,48`，底面 `40,48` |
| **左腿** | 左腿独立区：`20,48` 起（正面），右面 `16,52`，左面 `24,52`，背面 `28,52`，顶面 `20,48`，底面 `24,48` |
| **左袖（左臂外层）** | 左袖独立区：`52,48` 起（正面），右面 `48,52`，左面 `56,52`，背面 `60,52` |
| **左裤（左腿外层）** | 左裤是**独立区**（与左腿不共用）：正面 `4,52`，右面 `0,52`，左面 `8,52`，背面 `12,52`，顶面 `4,48`，底面 `8,48` |

**第二层（外层面）说明**：`帽子 / 外套 / 袖子 / 裤子` 是"第二层皮肤"，
它们的方块比本体每边大 0.25 像素，盖在本体外面，用透明像素就能做出头发、帽子、披风下摆。

### 贴图分区速查（16 个 16×16 格子，4×4 排列）

| 列 0–16 | 列 16–32 | 列 32–48 | 列 48–64 |
|---|---|---|---|
| 头（左上 8×8 等） | 头（其余面） | 帽子外层（上 8 行） | 帽子外层（其余） |
| 右腿 | 躯干（左 8 列） | 躯干（其余） | 右臂 |
| 右裤外层 | 外套外层 | 右袖外层 | 右臂外层 |
| 左裤外层 | **左腿** | **左臂** | **左袖外层** |

记住这个 4×4 格子表，比记坐标快得多。

### 64×32（旧版格式）

- 64×32 与 64×64 是**同一个像素网格**，只是旧版只填了左上/右上几块，其余留空。
  也就是说 `(0,0)–(64,16)` 是头部那一带，`(0,16)–(64,32)` 依次是右腿、躯干、右臂
  —— **没有**左臂/左腿/左袖/左裤/帽子/外套的贴图区。
- 左臂/左腿在旧版里跟右臂/右腿共用同一块贴图，但游戏里左右肢体是镜像摆放的，
  所以左臂看起来是右臂的**镜像**。
- 本工具载入 64×32 时会自动补成 64×64（`rules.convertLegacy64x32`）：
  1. 已有的 4 块**原样 1:1 保留**（不放大！）；
  2. 左臂 ← 右臂、左腿 ← 右腿，做**逐面水平镜像**（外↔内换位 + 每面自身左右翻转，
     这样贴图接缝才不会裂开）；
  3. 用基础层内容整块补上帽子/外套/袖/裤，所以旧皮肤也能显示外层。
  验证脚本：`node tools/verify_legacy.mjs`。

## 四、项目结构与开发

```
index.html          页面骨架（脚本顺序：util → rules → model → renderer3d → editor2d → shell）
css/app.css         全部样式
js/util.js          颜色 / 像素缓冲 / 直线 / DOM 小工具
js/rules.js         皮肤格式与 UV 映射的唯一真相（BOXES / regionAt / convertLegacy64x32）
js/model.js         像素数据模型（撤销栈、笔画、格式转换）
js/renderer3d.js    WebGL 立体预览（自己实现，零外部库）
js/editor2d.js      2D 像素绘制界面
js/shell.js         总装：文件读写、控件绑定、模块联动
CONTRACT.md         模块接口契约（并行开发用；也是"哪块像素是哪个部位"的权威定义）
tests/              端到端验收探针 + 参考皮肤视觉复核页（无头 Edge 运行）
tools/              开发工具：一键测试脚本、无头浏览器驱动、零依赖 PNG 编解码、
                    旧版转换验证、UV 展开网接缝验证、参考图区域探针
```

### 一键验收（推荐）

```powershell
node tools/run_tests.mjs            # 全部：语法 → 转换/接缝验证 → 175 条模块自测 → 无头浏览器端到端 60 项
node tools/run_tests.mjs --no-e2e   # 只跑不开浏览器的部分（快）
```

当前基线：**模块自测 175 通过 / 0 失败，端到端 60 项全部通过，无 JS 报错**。

### 分项验收（可单独复现）

```powershell
# 1) 旧版 64×32 → 64×64 转换（用自造多色块逐像素断言"左肢=右肢逐面镜像"）
node tools/verify_legacy.mjs

# 2) UV ↔ 几何 的展开网接缝验证（含敏感性检验：故意写错必须报错）
node tools/verify_unwrap.mjs

# 3) 端到端：真实 WebGL，含像素回读与几何投影校验
node tests/build_probe.mjs
node tools/headless.mjs index.html --apply tests/out/auto_probe_injected.js --width 1600 --height 1000
#    → tests/out/index.png 整页截图；stdout 的 probe 即逐项结果

# 4) 两张参考皮肤的 3D 视觉复核（6 张图：2 皮肤 × 3 视角）
node tests/build_visual.mjs
node tools/headless.mjs tests/out/visual_check_built.html --width 1400 --height 1650

# 5) 鼠标交互验收（命中测试 + 模拟真实拖拽/滚轮/自动旋转）
PROBE=drag node tests/build_probe.mjs
node tools/headless.mjs index.html --apply tests/out/auto_probe_injected.js --width 1600 --height 1000
```

探针覆盖：模块加载、各模块自测、贴图 UV 与几何一致性、2D 画布真的能改像素且能撤销、
3D 画面非空且有明暗、旋转/隐藏部位后画面改变、两张参考图能被正确读入与渲染、
旧版 64×32 转换逐像素正确，以及**几何投影校验**（6 个部位各涂一色正对相机渲染，
断言头部在躯干上方、腿在下方、角色右臂投影在画面左侧、左臂在右侧、左右腿分列两侧）。
交互探针还断言 **`document.elementFromPoint` 在预览区中心必须命中 `#glCanvas`**
（曾出现 `.viewport-error` 的作者样式 `display:grid` 盖过 `[hidden]`，一层 90% 黑幕
既压暗画面又吃掉鼠标事件——这类"合成事件测得到、真实鼠标点不到"的坑必须用命中测试防住）。

> 相机约定（写死并有自测保护）：`eye = target + d·(cosPitch·sinYaw, sinPitch, cosPitch·cosYaw)`，
> 即 **yaw=0 是正视（+Z = 角色正面）**、yaw=180 是背面、yaw=-90 是角色右侧面。

## 五、已知限制

- 需要浏览器支持 WebGL 才能看 3D 预览；不支持时页面会给出提示，2D 绘制仍可正常使用。
- 不支持 128×128 的高清皮肤（HD skin）。

## 六、DSH 插件 Skill：`mcskin-artist`（让 AI 绘制并审查皮肤）

基于本工具的格式/渲染能力封装的 **DeepSeek Harness 技能**：AI 可以纯命令行**绘制、审查、多轮修订**
Minecraft 皮肤，成品带质量门槛。

| 组件 | 说明 |
|---|---|
| `skill/mcskin-artist/` | skill 源码（工作区内开发；`CONTRACT.md`/`CONTRACT_CORE.md` 是接口契约） |
| `bin/skin.mjs` | 绘制 CLI：set/fill/rect/line/mirror-limbs/converter/palette/parts/crops/**lint**（13 项质量检查+评分）/run 批量脚本/selftest |
| `bin/skin-core.mjs` | 核心库（像素操作、统计、lint 引擎、裁切），供 CLI 调用 |
| `bin/render.mjs` | 审查渲染：**8 视角**（正/背/左右侧/两个 3/4/俯/仰）+ **4 姿态帧**（idle/walk×2/wave，冻结时间点）+ 贴图高清裁切 → PNG 给 AI 逐张看 |
| `SKILL.md` | 技能正文：多轮工作流、视觉审查清单、质量门槛（lint grade≥A、fail=0、warn≤2） |

```powershell
# 安装到 DSH 技能目录（装好即可被会话识别）
node tools/install_skill.mjs            # → ~/.dsh/skills/mcskin-artist
node tools/install_skill.mjs --check    # 安装前校验（frontmatter/引用/语法）
node tools/install_skill.mjs --dev      # 开发：只把依赖注入源码目录
```

安装后，新 DSH 会话里说「画一张 MC 皮肤 / 审查这张皮肤」等即可触发该 skill；
AI 会按 SKILL.md 的多轮协议：规划 → 批量绘制 → `lint` 评分 → `render` 出图 → `read_image` 逐视角检查 →
修改 → 再评，直到达到质量门槛。
